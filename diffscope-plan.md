## 1. Задача

Перенести в VS Code и Cursor удобный просмотр изменений git из WebStorm. Существующие бесплатные
расширения (GitLens, Git Graph и др.) пробовались — неудобные или не хватает функций.
Встроенное сравнение VS Code не умеет главного — лент, соединяющих изменённые блоки слева и
справа, — поэтому дифф делаем свой.

Использование — личное, один пользователь. Расширение **только читает** репозиторий: никаких
checkout, commit, stash, fetch. Хостинг — пока GitHub, но расширение работает с любым локальным
клоном, поэтому от хостинга почти не зависит.

Долгие операции допустимы, но у каждой должен быть видимый индикатор загрузки и возможность отмены.

## 2. Пожелания пользователя

### MVP

**A. История по выделенным строкам** (аналог «Show History for Selection» в WebStorm) — ✅

1. ✅ Выделить одну или несколько строк в редакторе → команда «Показать историю по строкам»
   (контекстное меню редактора «DiffScope ▸» и палитра команд; без выделения — строка с
   курсором; горячей клавиши по умолчанию нет — пользователь назначит сам).
2. ✅ В панели «DiffScope: История» появляется список коммитов, которые меняли эти строки (хеш,
   автор, дата, сообщение). Первой строкой — «Незакоммиченные изменения», если они затрагивают
   фрагмент. Повторный вызов заменяет содержимое панели.
3. ✅ Клик по коммиту (или ↑/↓ в списке) показывает дифф «предыдущая ревизия → выбранный коммит».
   Каждый вызов команды открывает новую вкладку диффа; переходы по списку этой истории обновляют
   её же вкладку, а не плодят новые.
4. ✅ Два режима диффа, флажок «Только выделенные строки» на панели вкладки:
   - **только выделенные строки** (по умолчанию, по отзыву) — дифф фрагмента в двух версиях;
   - **весь файл** — фрагмент подсвечен, дифф прокручен к нему.
5. ✅ Дополнительно: «Показать историю» — история всего файла с переименованиями; merge с
   правками при разрешении конфликта виден в обеих историях.

**B. Сравнение файла между двумя ревизиями** — ✅

1. ✅ Выбрать файл (проводник, вкладка редактора, палитра команд) → команда «Сравнить с…».
2. ✅ Открывается новая вкладка диффа: слева одна версия файла, справа другая.
3. ✅ По умолчанию — сравнение с предыдущей версией:
   - справа — рабочая копия (текущее состояние файла на диске);
   - слева — `HEAD`, если в файле есть незакоммиченные правки; иначе — версия до последнего
     коммита, менявшего файл (то есть видна последняя правка).
4. ✅ На панели вкладки — левая и правая ревизия; клик открывает выпадающий список VS Code:
   рабочая копия, ветки (локальные и удалённые), теги, недавние коммиты, поиск коммита по хешу или
   сообщению. После выбора дифф пересчитывается.
5. ✅ Кнопка «Поменять местами».

**C. Сравнение двух веток целиком** — ✅

1. ✅ Команда «Сравнить ветки» → выбор двух ревизий в выпадающем списке.
2. ✅ В панели «DiffScope: Изменённые файлы» — дерево отличающихся файлов со статусами: добавлен,
   изменён, удалён, переименован (цвет и буква, как в Source Control). Папки сворачиваются,
   в заголовке панели — счётчик файлов.
3. ✅ Клик по файлу — прокрутка вкладки «все файлы» к нему (по отзыву: все файлы сразу,
   сплошной прокруткой; отдельная вкладка файла — в контекстном меню и в заголовке файла).
4. ✅ Переключатель режима сравнения (кнопка в заголовке панели):
   - **как в PR** (`A...B`, по умолчанию) — только изменения ветки B с момента расхождения с A,
     как вкладка «Files changed» на GitHub;
   - **прямое** (`A..B`) — все отличия деревьев двух веток прямо сейчас, включая изменения,
     сделанные в A после ответвления.

**Общее для диффа во всех функциях** — ✅

- **Ленты между колонками**: каждый изменённый блок слева соединён цветной лентой с
  соответствующим блоком справа; удалённые и добавленные строки — лентой, сходящейся в линию.
  Цвет ленты — по типу изменения: цвета меток изменений текущей темы VS Code
  (`editorGutter.addedBackground` / `modifiedBackground` / `deletedBackground`).
- Синхронная прокрутка колонок по соответствующим блокам (как в WebStorm, без выравнивания
  пустыми строками).
- Три режима: «Ленты» (две колонки без выравнивания, ленты между блоками), «MergeView» (колонки
  выровнены, напротив вставки — пустое место, цветные полосы у номеров строк) и «1 колонка».
- Сводка изменений над диффом, как на GitHub: «+10 −3» и пять цветных квадратиков.
- Если изменений нет — файл показывается целиком, без сворачивания.
- **По умолчанию видны только изменения** и по 4 соседние строки вокруг каждого (число — в
  настройках). Свёрнутый участок в обеих колонках заменяется разделителем «⋯ N строк скрыто»;
  клик раскрывает его с обеих сторон. Флажок «Весь файл» на панели вкладки.
- Переход к следующему / предыдущему изменению: кнопки ↑ ↓ и F7 / Shift+F7, как в WebStorm;
  блок встаёт на треть высоты экрана в обеих колонках; счётчик «3 / 12».
- Метки изменений у полосы прокрутки каждой колонки — карта всего файла; клик переходит к
  изменению.
- Подсветка изменений внутри строки.
- Номера строк, подсветка синтаксиса, цвета под текущую тему VS Code (светлая / тёмная).

### После MVP

- ⬜ **D. Просмотр коммита целиком**: из списка коммитов открыть все файлы коммита деревом в
  панели и дифф каждого (так же, как сравнение веток — во вкладке «все файлы»).
- ✅ История целого файла (аналог «Show History» в WebStorm); ⬜ история папки.
- ⬜ Автор у выделенных строк (blame) и подсказка при наведении.
- ⬜ Ссылки «открыть коммит на GitHub».
- ⬜ Восстановление открытых вкладок диффа после перезапуска VS Code.
- ⬜ F7 / Shift+F7 по файлам во вкладке «все файлы».
- ⬜ Обновление диффа с рабочей копией при правке файла.

### Не делаем

- Изменение репозитория: checkout, commit, merge, stash, разрешение конфликтов. Поэтому у лент
  нет стрелок «перенести изменение», как в WebStorm.
- Сетевые операции: `git fetch` не запускается; удалённые ветки — по состоянию последнего fetch
  пользователя.
- Работа через API GitHub без локального клона.

## 3. Интерфейс

```
┌─ вкладка диффа (своя, webview) ─────────────────────────────────┐
│ [левая ревизия]  ⇄  [правая ревизия]   2 кол. | 1 кол.   ↑ ↓    │  панель вкладки
├──────────────────────────┬──┬───────────────────────────────────┤
│ левая версия             │╲ │ правая версия                     │
│ ████ изменённый блок     │ ═│ ████ изменённый блок              │  дифф с лентами
│                          │╱ │                                   │
└──────────────────────────┴──┴───────────────────────────────────┘
┌─ нижняя панель VS Code (рядом с Terminal) ──────────────────────┐
│ DiffScope: История        │ хеш │ автор │ дата │ сообщение       │  A
│ DiffScope: Изменённые файлы — дерево со статусами               │  C
└─────────────────────────────────────────────────────────────────┘
```

| Функция                       | Где список                                              | Вкладка диффа                                 |
| ----------------------------- | ------------------------------------------------------- | --------------------------------------------- |
| A. История по строкам         | панель «История»                                        | файл и диапазон строк, «весь файл / фрагмент» |
| B. Сравнение файла            | —                                                       | две ревизии, ⇄                                |
| C. Сравнение веток            | панель «Изменённые файлы», `A...B` / `A..B` в заголовке | ревизии веток                                 |
| D. Коммит целиком (после MVP) | панель «Изменённые файлы»                               | коммит и его родитель                         |

Панели — в своём разделе нижней панели VS Code; пользователь может перетащить их в боковую
панель, VS Code это запомнит.

## 4. Архитектура

### Как это работает

- **Расширение (Node.js)** работает в процессе расширений VS Code. Активируется при первом вызове
  команды. Регистрирует команды и панели (TreeView), показывает выпадающие списки ревизий
  (QuickPick), запускает `git`, открывает вкладки диффа.
- **Вкладка диффа (webview)** — React-приложение с CodeMirror 6, заранее собранное Vite
  в статические файлы внутри пакета `.vsix`. Никакого сервера нет.
- **Связь** — сообщения `postMessage` между вкладкой и расширением.

```
вкладка  ── { id, type: 'pickRef', side: 'left' } ─────────▶  расширение показывает QuickPick
вкладка  ◀── { type: 'load', left: {rev, text}, right: {...}, highlight } ──
вкладка  ── { id, type: 'cancel' } ────────────────────────▶  kill процесса git
```

### Решения

| Вопрос                         | Решение                                                                                                                                                                                                                                            | Почему                                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Платформа                      | Расширение VS Code, ставится в VS Code и Cursor из `.vsix`                                                                                                                                                                                         | Оба редактора — основные                                                                                                |
| Списки коммитов и файлов       | Родные панели VS Code (`TreeView`), статусы файлов — `FileDecorationProvider`                                                                                                                                                                      | Меньше кода, выглядит и управляется как остальной VS Code                                                               |
| Выбор ревизий                  | Родной `QuickPick` с разделами и поиском коммитов по мере ввода                                                                                                                                                                                    | Готовый выпадающий список с поиском                                                                                     |
| Дифф                           | Своя вкладка-webview: React + CodeMirror 6 + `@codemirror/merge`, ленты — SVG в промежутке между колонками                                                                                                                                         | Встроенный дифф VS Code не позволяет рисовать между колонками                                                           |
| Способ построения двух колонок | Два отдельных `EditorView` + блоки из `Chunk.build` (`@codemirror/merge`), своя синхронная прокрутка и SVG-ленты (`webview/src/diff/sideBySide.ts`). Решено на прототипе (этап 1)                                                                  | `MergeView` выравнивает колонки пустыми вставками и прокручивает их одним скроллом — ленты вырождаются в прямоугольники |
| Одна колонка                   | `unifiedMergeView` из `@codemirror/merge`                                                                                                                                                                                                          | Готовый режим                                                                                                           |
| Подключение CodeMirror к React | Свой компонент-обёртка (`ref` + `useEffect`)                                                                                                                                                                                                       | Около 30 строк, полный контроль над обновлениями                                                                        |
| Подсветка синтаксиса           | Языковые пакеты `@codemirror/lang-*`, загружаются по требованию; неизвестный язык — простой текст                                                                                                                                                  | Основные языки: TS/JS, JSON, CSS, HTML, Markdown, YAML, Go, Python                                                      |
| Цвета                          | Цвета интерфейса, диффа и лент — из CSS-переменных VS Code (`--vscode-editor-background`, `--vscode-diffEditor-insertedTextBackground` и т. д.); цвета синтаксиса — свои светлая и тёмная схемы по классу `vscode-dark` / `vscode-light` на `body` | Webview знает цвета интерфейса темы, но не цвета подсветки кода                                                         |
| Доступ к git                   | Системный `git` через `child_process.execFile`                                                                                                                                                                                                     | Есть `log -L`, `blame`, переименования; быстро                                                                          |
| Вкладки диффа                  | Новая вкладка на каждый вызов команды; состояние сохраняется через `setState` webview, без `retainContextWhenHidden`                                                                                                                               | Вкладок может быть много — не держать их все в памяти                                                                   |

### Что теряется по сравнению со встроенным диффом

- Цвета синтаксиса не совпадут с темой VS Code один в один (цвета интерфейса и диффа — совпадут).
- В диффе нет перехода к определению и подсказок языка — для просмотра не критично.
- Больше кода: дифф, ленты, синхронная прокрутка и клавиатура — свои.

### Протокол сообщений вкладки диффа

Каждый запрос вкладки имеет `id`; ответ — `result` или `error` с тем же `id`. Новый запрос того же
типа отменяет предыдущий (`cancel`). Расширение шлёт вкладке события без запроса: «показать дифф»
(при открытии и при выборе коммита в панели «История»), «сменилась тема».

| Запрос вкладки      | Что делает расширение                                    |
| ------------------- | -------------------------------------------------------- |
| `load`              | содержимое обеих сторон (и фрагмент истории)             |
| `pickRef(side)`     | QuickPick ревизий; после выбора вкладка делает `load`    |
| `swap`              | меняет ревизии местами                                   |
| `saveLayout(split)` | запоминает ширину колонок для всех вкладок               |
| `multiList`         | «все файлы»: список файлов сравнения с «+N −M»           |
| `multiFile(index)`  | «все файлы»: содержимое сторон файла (по мере прокрутки) |
| `openFile(index)`   | «все файлы»: открыть файл в отдельной вкладке            |

События расширения: `init` (вид вкладки, раскладка), `reload` (другой файл или ревизии),
`reveal(index)` (клик в дереве — прокрутить к файлу).

### Git-команды по функциям

| Функция                        | Команды                                                                                                                                            |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. Коммиты по строкам          | `git log -L <с>,<по>:<путь> --format=<разделители>` — из патчей берутся коммиты, путь файла на каждой ревизии и диапазон фрагмента в каждой версии |
| A. Незакоммиченные правки      | дифф `HEAD:<путь>` с текущим текстом буфера (в JS, библиотека `diff`)                                                                              |
| B. Предыдущая версия файла     | `git log -2 --format=%H -- <путь>`, `git status --porcelain -- <путь>`                                                                             |
| A, B, C. Содержимое на ревизии | `git show <рев>:<путь>`; рабочая копия — текст открытого буфера или файл с диска                                                                   |
| Выбор ревизии                  | `git for-each-ref refs/heads refs/remotes refs/tags`, `git log -n 50`, `git log --grep`                                                            |
| C. Отличающиеся файлы          | `git diff --name-status -z -M <A>...<B>` или `<A> <B>`                                                                                             |
| D. Файлы коммита               | `git diff-tree --no-commit-id -r -z -M --name-status <коммит>`                                                                                     |

Сам дифф двух версий файла считает CodeMirror во вкладке; git нужен для списков файлов, коммитов
и содержимого.

### Ключевые алгоритмы

**Ленты.** Из блоков изменений (`Chunk`: диапазон строк слева и справа) для каждого блока берутся
экранные координаты верха и низа в обеих колонках (`lineBlockAt` / `coordsAtPos`). Между ними в
SVG рисуется фигура: верхняя и нижняя кривые Безье и заливка цветом изменения. Перерисовка — при
прокрутке, сворачивании участков и изменении размера окна, через `requestAnimationFrame`;
рисуются только блоки, видимые хотя бы с одной стороны.

**Синхронная прокрутка.** Строка в середине экрана ведущей колонки переводится в строку второй
колонки по таблице блоков: вне блоков — сдвигом, внутри блока — пропорционально его высоте с обеих
сторон. Ведомая колонка прокручивается так, чтобы эта строка тоже оказалась посередине.

**Выделение в изменённом файле (A).** `git log -L` считает номера строк по `HEAD`, а в редакторе
могут быть незакоммиченные правки. Перед запросом выделение переводится в номера `HEAD` через дифф
буфера с `HEAD`. Строки, которых нет в `HEAD`, отбрасываются; если выделение целиком новое —
в списке только «Незакоммиченные изменения».

**Подсветка фрагмента в диффе всего файла (A).** Диапазон фрагмента в обеих версиях известен из
вывода `log -L`; в CodeMirror он подсвечивается декорацией, дифф прокручивается к нему.

**Дифф только выделенных строк (A).** Из обеих версий вырезается диапазон фрагмента, номера строк
показываются исходные (смещение в настройке нумерации CodeMirror).

**Файл есть только с одной стороны (B, C).** Добавленный или удалённый файл сравнивается с пустым
текстом; переименованный — по старому и новому пути.

### Загрузка и отмена

- Панели «История» и «Изменённые файлы» показывают полосу загрузки (`withProgress` с
  `location: { viewId }`); во вкладке диффа — индикатор поверх диффа. Если операция идёт дольше
  ~1 с — кнопка «Отменить» (уведомление VS Code с отменой или кнопка во вкладке).
- Смена ревизии или выделения отменяет текущий запрос: процесс git завершается.
- Ошибки git — сообщение с текстом stderr и ссылкой на лог расширения (Output channel).

### Пограничные случаи

- Переименования: `-M`; у `log -L` путь на каждой ревизии берётся из заголовков патча.
- Двоичные и очень большие файлы — заглушка вместо диффа (порог размера — в настройках).
- Большие диффы: ленты рисуются только для видимых блоков.
- Merge-коммиты в истории — настройка «только первый родитель» (по умолчанию выключена: видны
  коммиты влитых веток, в том числе тот, где строки появились).
- Сабмодули и вложенные репозитории — корень ищется от файла.
- Shallow-клон — предупреждение, что история обрезана.
- Detached HEAD, git worktree, Git LFS (показывать указатель LFS как текст).
- Кодировки: содержимое из `git show` декодируется как UTF-8; другие кодировки — после MVP.
- Окончания строк CRLF/LF не должны давать дифф «весь файл изменён».
- Смена темы VS Code при открытой вкладке — перекраска без перезапуска.

### Безопасность webview

- Content Security Policy: скрипты только с `nonce`, без внешних адресов.
- `localResourceRoots` — только папка со сборкой вкладки.
- Вкладка не выполняет команды git сама: только типизированные запросы из протокола.

### Настройки

- ✅ Режим сравнения веток по умолчанию (`diffscope.branchCompare.defaultMode`: `pr` / `direct`).
- ✅ Только первый родитель для истории (`diffscope.history.firstParent`, по умолчанию выключено).
- ✅ Ширина колонок — запоминается сама (перетаскивание разделителя).
- ⬜ Режим диффа по умолчанию (Ленты / MergeView / 1 колонка).
- ⬜ Максимум коммитов в списке (подгрузка порциями; сейчас до 500 / 1000).
- ⬜ Порог размера файла для диффа (сейчас 5 МБ).
- ⬜ Число строк контекста вокруг изменений (сейчас 4).
- ⬜ Формат даты (сейчас по языку VS Code).

## 9. Решения и открытые вопросы

Решено:

1. Дифф — свой, с лентами между колонками, как в WebStorm; без промежуточного этапа на встроенном
   диффе VS Code.
2. Название — **diffscope-extension**.
3. Значения по умолчанию в «Сравнить с…» — правило из пункта B.3.
4. Режим сравнения веток по умолчанию — как в PR (`A...B`).
5. Горячей клавиши по умолчанию нет — команда в контекстном меню и палитре.
6. Каждый вызов команды открывает новую вкладку диффа.
7. Списки и выбор ревизий — родной интерфейс VS Code (панели и QuickPick).
8. Две колонки — два независимых редактора с лентами и синхронной прокруткой, не `MergeView`
   (прототип, этап 1). На файле в 5400 строк: дифф ~12 мс, прокрутка ~60 кадров/с.
9. Дифф как в git и WebStorm: сначала по строкам (`diff` из `@codemirror/merge` на строках,
   закодированных символами), затем `presentableDiff` по символам внутри изменённых блоков.
   `Chunk.build` (сначала по символам) склеивал соседние изменения в один блок.
10. Цвета изменений — из темы VS Code; неизменённое по умолчанию свёрнуто, контекст 4 строки;
    навигация — F7 / Shift+F7 и метки у полосы прокрутки (не миникарта между колонками: там
    ленты).
11. git — тот же, что у встроенного git-расширения VS Code (`git.path`), иначе из PATH. Команды
    совместимы с git 2.15+ (на машине пользователя первым в PATH стоит 2.15): без `init -b`,
    `worktree remove`, `--end-of-options`. Тесты гоняются на 2.15 и 2.32.
12. Содержимое файла на ревизии — `cat-file --batch-check` (хеш blob и размер) + `cat-file blob`,
    кеш по хешу blob (LRU, 64 МБ). Двоичный — NUL в первых 8000 байт, как в git.
13. Поиск коммита по тексту: ASCII — `git log --grep -i`; другой текст (кириллица) — фильтр
    заголовков последних 20 000 коммитов в JS: `--grep -i` различает регистр только у ASCII.

14. Вкладка диффа (этап 3): ревизии над своими колонками, клик открывает QuickPick с разделами и
    поиском коммитов по мере ввода; ⇄; «2 колонки / 1 колонка»; «Весь файл»; навигация. Одна
    колонка — `unifiedMergeView` с нашим диффом по строкам (`diffConfig.override`), поэтому
    блоки те же, что в двух колонках; исключение — блоки через пустую строку CodeMirror
    склеивает. Языки подсветки — отдельными частями сборки по требованию.
15. Рабочая копия — текст открытого документа (с несохранёнными правками), иначе файл с диска.
    Обновление диффа при правке файла — на этапе 7.

16. Режимы диффа — «Ленты», «MergeView», «1 колонка»; MergeView вернули по просьбе пользователя
    как отдельный режим. Сводка «+N −M» с квадратиками, как на GitHub. F7 / Shift+F7 — ровно на
    один блок от числа на счётчике.

17. «Сравнить с…» по умолчанию (этап 4): состояние файла — `git status --porcelain --ignored`;
    без правок — последний коммит, менявший файл (`git log -1 HEAD -- путь`), и его первый
    родитель; путь в родителе — из `git diff --name-status -M` всего коммита (с ограничением путём
    git не видит старое имя). У каждой стороны свой путь: слева над колонкой «был старый/путь».
    Корневой коммит и добавленный файл — слева «нет файла». Shallow-клон — уведомление.

18. История по строкам (функция A) сделана раньше сравнения веток. Панель «История» — в своём
    разделе нижней панели; выбор строки списка обновляет вкладку этой истории, новый вызов
    команды — новая вкладка; «Открыть в новой вкладке» в контекстном меню строки. В истории
    «Весь файл» включается сам, фрагмент — рамка слева и прокрутка к нему; «Только выделенные
    строки» — дифф кусков с настоящими номерами строк; пути и диапазоны — из патча каждого коммита.

19. «Показать историю»: есть выделение — история строк (`git log -L`), нет — история всего файла
    (`git log --follow --name-status`, с переименованиями); из проводника и вкладки — история
    файла. В строке списка сначала дата и автор, затем сообщение коммита и короткий хеш.

20. История по умолчанию — по всем коммитам, не только по первому родителю: с `--first-parent`
    `log -L` останавливается на merge-коммите без патча, и строки из влитой ветки (PR) выглядели
    «без истории». Настройка `diffscope.history.firstParent` (по умолчанию выключена); с ней
    merge показывается против настоящего первого родителя (`<хеш>^1`). Слева у коммита истории
    строк — `<хеш>^`: `log -L` подставляет в `%P` предыдущий коммит, менявший эти строки.
    Пустой диапазон у `log -L` (`-3,0`) — место перед строкой 3. Для истории строк по умолчанию
    включён флажок «Только выделенные строки». Merge-коммиты без патча в истории строк — только с
    `firstParent`: без него коммиты влитой ветки видны сами, и список совпадает с историей файла.

21. Ширина колонок — перетаскиванием: в «Лентах» тянется промежуток с лентами, в MergeView —
    разделитель между колонками; двойной клик — поровну. Доля общая для всех вкладок
    (`globalState` расширения, запрос `saveLayout`). Колонки MergeView делят ширину по доле, а не
    по длине строк: длинные строки прокручиваются внутри колонки.

22. Merge с правками при разрешении конфликта показывается и в истории строк, и в истории файла:
    строки версии в merge, которых нет ни в одном родителе (дифф с каждым родителем), — правка
    самого merge. История строк — среди merge без патча из `log -L`, фрагмент переводится в
    версию merge; история файла — `git log --merges -- путь`, merge вставляется по дате без
    перестановки остальных. Обычный merge (каждая строка из какой-то ветки) не показывается.
    Слева — первый родитель (`<хеш>^1`). Промежуток с лентами — 32px.

23. Сравнение веток (функция C): команда «Сравнить ветки» (палитра, заголовок Source Control,
    панель). База по умолчанию — ветка, на которую указывает origin/HEAD, иначе main / master /
    develop; справа — текущая ветка, а если она и есть база — рабочая копия. Базой рабочая
    копия быть не может. Панель «Изменённые файлы» рядом с «Историей»: дерево (цепочки папок
    сжаты) или список, буква и цвет статуса — цвета git из темы; переименование — «← старый
    путь». Кнопки: сменить ветки, режим PR / прямое, поменять местами, дерево / список,
    обновить. Как в PR — левая сторона общий предок (`merge-base`), подпись — имя базы. Нет
    общей истории — прямое с пометкой. Клик — дифф во вкладке сравнения; новая — в контекстном
    меню. Неотслеживаемые файлы рабочей копии в список не попадают (`git diff`).

24. Вкладка «все файлы» сравнения веток (как «Files changed» на GitHub): открывается сразу после
    сравнения, сплошная прокрутка, у файла — закреплённый заголовок (статус, путь, «+N −M» из
    `git diff --numstat`, «Весь файл», «В отдельной вкладке», скрыть). Дифф — «Ленты» по высоте
    содержимого: внутри изменений колонки независимы, на ближайшем неизменённом участке (у
    разделителя «⋯ скрыто» или там, где он был бы) и в конце файла короткая колонка добирается
    пустым местом — расхождение не копится (`alignmentPads`). Файлы загружаются и рисуются по
    мере прокрутки. Дерево в панели — оглавление: клик прокручивает к файлу; отдельная вкладка —
    в контекстном меню. F7 по файлам этой вкладки — позже.

25. Контекстное меню: один пункт **DiffScope ▸** с подменю — «Сравнить с…», «Показать историю»
    (весь файл), «Показать историю по строкам» (выделение; без него — строка с курсором; только
    в редакторе) и через разделитель «Сравнить ветки». История файла и история строк — две
    команды.
